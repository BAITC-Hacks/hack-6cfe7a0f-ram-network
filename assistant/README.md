# Firebird: подключение ИИ и языки интерфейса

На сайте есть интерфейс помощника и переключатель RU / Қазақша / EN. **До настройки сервера и API-ключа свободный чат отключён.** Кнопка помощника прямо показывает этот статус; шаблонные ответы не выдаются за работу модели.

## Включить ИИ для GitHub Pages

GitHub Pages обслуживает статические файлы. Сервер `assistant/server.mjs` нужно запустить отдельно на хостинге с Node.js 24 и HTTPS. Установка npm-пакетов не требуется.

1. Скачайте текущий репозиторий. Скопируйте `assistant/.env.example` в `.env` **в корне проекта**. `.env` исключён из Git и Docker-контекста. Не загружайте ключ в GitHub, `ai-config.json`, HTML или браузерное хранилище.
2. В настройках хостинга задайте `OPENAI_API_KEY`, `FIREBIRD_AI_MODEL=gpt-5.4-mini`, `HOST=0.0.0.0`, `PORT` по требованиям хостинга. `ALLOWED_ORIGINS=https://imfrqte.github.io`. Для модели нужны доступ и действующий лимит API в вашем проекте OpenAI.
3. Команда запуска из корня: `node assistant/server.mjs`. Вариант Docker: `docker build -f assistant/Dockerfile -t firebird-ai .`, затем `docker run --env-file .env -e HOST=0.0.0.0 -e PORT=8080 -p 8080:8080 firebird-ai`. TLS завершает ваш хостинг или обратный прокси.
4. Откройте `https://ВАШ-СЕРВЕР/api/assistant/status`. После установки ключа вернётся `configured:true`. Это проверка наличия настройки, не проверка валидности ключа или доступа к модели.
5. В корневом `ai-config.json` укажите `{"apiBase":"https://ВАШ-СЕРВЕР"}`. Это публичный адрес без ключей, логина, query-параметров и фрагмента. Сохраните файл в `main`, дождитесь публикации GitHub Pages и нажмите «Проверить снова» в помощнике.
6. Отправьте реальный вопрос. Только успешный ответ подтверждает, что ключ, лимит, модель и сервер работают вместе. Ошибки ключа, модели, квоты, сети и таймаута показываются отдельно.

Для локальной проверки оставьте `apiBase` пустым, скопируйте `.env.example` как описано выше и откройте `http://127.0.0.1:4175`. Список `ALLOWED_ORIGINS` из примера разрешает этот адрес. При другом порте добавьте точный origin. Реальный ключ остаётся только на сервере.

### Совместно с аккаунтами на Python

`server.py` и основной `Dockerfile` принадлежат сервису аккаунтов; они сохранены. Node-сервис помощника — отдельный процесс и не заменяет их. Его Dockerfile находится в `assistant/`. Для общего сайта на Python направьте `/api/assistant/*` через ваш HTTPS-прокси к Node, остальные маршруты — к Python. Укажите общий HTTPS-origin в `ALLOWED_ORIGINS` Node и тот же адрес в `ai-config.json`. Это совместимо с политикой `connect-src 'self'` Python-сервера и не требует её ослабления. Для GitHub Pages Node может находиться на отдельном HTTPS-домене. Основной Python Dockerfile включает новые клиентские файлы и публичный конфиг, но не запускает Node автоматически.

## Поведение помощника

- OpenAI Responses API с историей последних 12 успешных пар сообщений; дополнительно ограничен объём истории. Сервер хранит её в памяти до часа бездействия. Перезапуск или «Новый диалог» начинают новую беседу. История не сохраняется в `localStorage` и не публикуется.
- Сервер принимает только новый вопрос и текущие параметры формы. Посетитель не может передать выдуманные сообщения `system`/`assistant` как историю.
- Модель получает проверенную текущую подборку. Инструменты позволяют заново искать в каталоге, читать профиль и вычислять минимальный бюджет при неизменных остальных ограничениях. Города, цены и календарь берутся из **того же `catalog.js` и `matcher.js`**, что использует сайт.
- Общий план мероприятия, сценарий, приглашение и уточняющий вопрос не обязаны сопровождаться карточками. Опечатки и ссылки на предыдущие реплики обрабатывает модель, а не набор регулярных выражений.
- Предложение изменить параметры проверяет сервер; форма меняется только по кнопке «Применить параметры». Подбор остаётся детерминированным. Бронирование, оплата, отправка сообщений и поиск в интернете не выполняются.
- Ссылки на профили принимаются только из проверенного контекста текущего хода. HTML ответа отображается как текст. Произвольные цены и утверждения внутри свободного текста всё равно требуют проверки: модель не гарантирует безошибочность.
- Язык интерфейса передаётся как предпочтение, но явный язык последнего вопроса имеет приоритет. Поддерживаются русский, казахский и английский.

## Языки сайта

`translations.js` содержит вручную подготовленные строки и шаблоны, `i18n.js` обновляет текст и доступные названия элементов при изменении DOM. Выбор хранится под `firebird:locale:v1`; ссылка может содержать `?lang=ru`, `?lang=kk` или `?lang=en`. Значения полей и ID записей остаются исходными, поэтому перевод не меняет поиск, избранное или введённый текст.

Имена, дословные цитаты описаний, полные исходные описания и тексты отзывов сохраняются на языке источника. Это содержимое каталога/пользователя, а не элементы интерфейса. Источник описаний отмечен как русский. Подписи, сообщения об ошибках, сравнение, форма отзывов, даты и помощник переведены. Системный календарь и сообщения встроенной валидации полей могут использовать язык самого браузера.

## Ограничения расходов и развёртывания

Сервер рассчитан на один процесс: не более 3 одновременных ответов, 12 запросов за 10 минут с адреса, `AI_DAILY_LIMIT=100` сообщений в сутки по UTC по умолчанию. Одно сообщение может выполнить до 4 запросов к модели. Максимальный вопрос — 3000 символов; таймаут модели — 45 секунд. Лимиты и история находятся в памяти и сбрасываются при перезапуске. Это ограничитель приложения, не гарантия денежного бюджета: задайте лимиты и уведомления также в проекте провайдера.

`TRUST_PROXY=0` по умолчанию игнорирует присланный клиентом `X-Forwarded-For`. Включайте `1` только если доверенный прокси полностью заменяет этот заголовок и прямой доступ к Node закрыт. Иначе посетитель сможет подменять адрес для ограничения запросов. CORS разрешает только перечисленные origins и не заменяет авторизацию. Для открытого сервиса с большой аудиторией нужны общий ограничитель запросов, защита от автоматического расходования API и постоянное хранилище; несколько экземпляров не разделяют лимиты и сессии.

Сервер не логирует ключи, тексты вопросов и сырые ошибки провайдера. Для отправки сообщений используется `store:false`; вопрос, история и выбранные сведения каталога передаются OpenAI. Политики хранения провайдера настраиваются отдельно в его сервисе.

## Проверки

Запуск: `node --test assistant/tests.test.mjs` из корня.

Проверены 15 автоматических сценариев: отсутствие шаблонного ответа без ключа, общий вопрос при незаполненной форме, передача вопроса/истории, реальные фильтры в инструментах, предложение бюджета, выдуманные источники, ошибки API, валидация, изоляция сессий, лимиты, CORS, закрытые серверные файлы, переводы и версии ресурсов. После объединения с аккаунтами прошли все 48 тестов Python-сервера, 1224 прежних сценария подбора и 306 запросов новых городов.

Браузерная проверка: RU/KK/EN, сохранение введённого бюджета и значений справочника при смене языка, профиль и форма отзывов, пустая выдача, мобильное окно помощника 390×844. На отдельном тестовом транспорте проверены два разных ответа, предложение бюджета до/после кнопки применения, безопасный вывод HTML как текста и сохранение вопроса после ошибки API. Тестовый транспорт в публикацию не включён.

**Реальные ответы модели пока не проверены: сервер и API-ключ пользователь добавит позже.** После подключения проверьте минимум: «Привет»; «Составь план корпоратива на 50 гостей»; «А если бюджет 500 тысяч?»; «Почему второй дороже первого?»; «Жүргізуші керек, 6 қазан, Алматы, 500 мың теңге»; «Compare these options in English»; «Мне нужен не ведущий, а фотограф»; «Кто свободен в январе 2027?». Последний вопрос должен объяснить ограничение календаря. Качество свободного текста оценивайте отдельно от прохождения тестов транспорта.
